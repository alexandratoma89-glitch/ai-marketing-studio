# Connect @divinework.store to The Divine Work

## What is implemented

The old dashboard had only a toast saying OAuth would be added later and in-browser sample approvals. It had no Instagram API, credentials, tokens, persistent scheduling or publishing history. These demo items remain demos and are never queued automatically.

New `/studio/instagram` uses **Instagram API with Instagram Login**, not Facebook Login and not a Facebook Page token. Official authorization is at `www.instagram.com/oauth/authorize`, code exchange at `api.instagram.com/oauth/access_token`, long-lived exchange/refresh at `graph.instagram.com`, and versioned API calls at `graph.instagram.com/v24.0`. Only `instagram_business_basic` and `instagram_business_content_publish` are requested. A Professional Business or Creator account is required. API/version and platform rules must be confirmed in the real Meta app before the first publishing test; provider responses have only been mocked here.

State is random, browser-cookie-bound, ten-minute, hashed in Postgres and single-use. The HttpOnly SameSite=Lax cookie is Secure in production. Callback, account status and administrative APIs all require the existing Studio login. Tokens are AES-256-GCM encrypted with a separate server key and stored in service-role-only Supabase tables. Neither token nor app secret is returned to the browser. Token expiry is shown; refresh is attempted during enabled worker runs in the final seven days (only after 24 hours), otherwise reconnect explicitly. Wrong accounts, personal accounts and missing permissions are rejected.

The queue stores immutable video URL + caption + AI disclosure before explicit approval. Approval, account ID and schedule are persisted server-side. The authenticated worker claims only due approved content. Expensive upload/encoding happens before publishing; a database check immediately before `media_publish` rechecks approval/lease/account. Cancellation before publishing invalidates the lease. Once publishing has started, it cannot be reliably recalled; delete an unwanted published post in Instagram.

Transient errors before publishing use bounded exponential backoff. Container readiness is polled on later scheduler runs, not in an endless request. A publish intent is committed before the external request. Lost responses or crashed publication calls are quarantined as `uncertain` and never blindly retried. Check Instagram manually in that situation. Known media IDs are retained and missing permalinks are recovered without republishing. History stores safe event/error codes, not provider response bodies or credentials. The queue is capped to five processing attempts (up to ten for permalink recovery); failed/expired containers need a new draft and approval. Safe pre-container failures can be explicitly retried while retaining original approval.

AI disclosure is appended in Romanian to all material marked AI-generated. **Caption disclosure is not a substitute for a mandatory native Meta AI label.** The API adapter does not invent an undocumented native-label parameter. Material identified as requiring that native label (photorealistic synthetic video / realistic synthetic audio) is blocked from automated submission; publish it manually with Meta's required label. Preserve original provenance/C2PA metadata on hosted files. The owner must review AI disclosures, rights and the exact video before approval. Other marketing channels are untouched.

## Your numbered setup checklist (no code to write)

1. **Instagram:** log into `@divinework.store`. Open **Settings and activity → Account type and tools** and confirm it is **Business** or **Creator**. Enable two-factor authentication. You do not need to connect a Facebook Page for this integration.
2. **Meta for Developers:** open <https://developers.facebook.com/apps/> → **Create App**. Choose the Instagram API use case (Meta may call this **Access the Instagram API**) and your business portfolio if prompted. Complete the app name and contact email. In the dashboard choose **Instagram → API setup with Instagram login**, not Facebook Login.
3. In that Instagram setup page, open **Set up Instagram business login**. Add exactly `https://www.thedivinework.com/api/studio/instagram/callback` to **Valid OAuth Redirect URIs**. Under app settings add `thedivinework.com` as the app domain, `https://www.thedivinework.com/` as website URL, `https://www.thedivinework.com/instagram-data-deletion` as the integration privacy URL, and the main site's terms URL `https://www.thedivinework.com/termeni` where requested. These pages must be deployed and publicly reachable first. The existing website privacy page is linked from the integration privacy page.
4. In the Instagram login configuration set **Deauthorize callback URL** to `https://www.thedivinework.com/api/integrations/instagram/deauthorize`. For **User data deletion**, select the callback option and enter `https://www.thedivinework.com/api/integrations/instagram/delete`. These endpoints verify Meta signed requests before deleting connection tokens, queued Reels and Instagram history; they do not remove booking/payment records or Instagram posts.
5. In **App roles / Roles / Instagram testers**, add your Instagram account as an authorized tester if required by the app's development mode. Log into Instagram and accept the invitation under **Apps and websites → Tester invites** (the wording/location may vary by Meta account). In the API setup check that **instagram_business_basic** and **instagram_business_content_publish** are available. For accounts outside your app roles, use **App Review → Permissions and Features → Request Advanced Access** and complete any requested business verification, screencast and reviewer instructions before making the app Live. Owned test accounts can be tested in Development mode where Meta permits it.
6. On **Instagram → API setup with Instagram login**, find the **Instagram App ID** and **Instagram App Secret**. Use these Instagram credentials, not a Facebook Page access token. Do not put secrets in chat, GitHub files, screenshots, or `NEXT_PUBLIC_` variables.
7. **Supabase:** use your intended website project → **SQL Editor → New query**. Open the repository file `supabase/migrations/202610160004_instagram.sql`, copy its complete contents into the editor and click **Run**, once. This is the provided migration; you do not need to write SQL. Keep the existing Supabase URL and service-role key in Vercel. Instagram is independent of the commerce migrations and does not update subscriptions or prices.
8. **Video hosting:** in Supabase **Storage → New bucket**, create a separate public bucket for marketing videos only. Upload a finished MP4/MOV with stable public access and copy its public URL. Never put customer records there. Keep approved files immutable; use a new filename for each new version. Meta needs to download the original file without cookies, passwords or short-lived links. Your exact project host, e.g. `your-project.supabase.co`, is the value for `INSTAGRAM_VIDEO_HOSTS`. Multiple permitted hosts can be separated with commas.
9. **Vercel:** open **starpower → ai-marketing-studio → Settings → Environment Variables → Add Environment Variable**. Select **Production** (and Preview only if separately configuring its callback/domain). Add these server values as Secrets: `INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET`, `INSTAGRAM_TOKEN_ENCRYPTION_KEY`, and, if absent, `CRON_SECRET`. Generate the encryption key in a trusted password manager as **64 random hexadecimal characters** (`0–9`, `a–f`). `CRON_SECRET` needs at least **32 random characters**. Save them in your password manager too. Losing/changing the encryption key requires reconnecting; do not rotate it without a re-encryption/reconnection plan. Do not change the existing Studio password or payment/email variables.
10. Still in Vercel variables add Config values: `TAROT_SITE_URL=https://www.thedivinework.com` (keep it if already set), `INSTAGRAM_EXPECTED_USERNAME=divinework.store`, `INSTAGRAM_GRAPH_VERSION=v24.0`, `INSTAGRAM_DATABASE_READY=true`, `INSTAGRAM_VIDEO_HOSTS=` your exact storage hostname, and **`INSTAGRAM_PUBLISHING_ENABLED=false`**. Keep this last value false during connection setup. Existing `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `STUDIO_USERNAME` and `STUDIO_PASSWORD` are also required; never replace them with examples.
11. **Vercel → Deployments:** open the deployment containing this integration → **Redeploy** after saving variables. The supplied Vercel cron runs `/api/jobs/instagram` once per minute using `CRON_SECRET`. **Minute scheduling requires a Vercel plan supporting it (normally Pro); Hobby does not support this frequency.** If your Pro trial has ended, confirm a suitable hosting/scheduler plan before deploying the minute cron. No plan upgrade or purchase was made by this task. In **Settings → Cron Jobs**, confirm this job exists after deployment; cron configuration is version-controlled and is included already, so you do not write code.
12. Open <https://www.thedivinework.com/studio/instagram>, sign in with your existing Studio credentials and click **Conectează / reconectează Instagram**. Log into **@divinework.store**, grant the two permissions, and finish the redirect back to Studio. Only then should it say **Autorizare OAuth finalizată; publicare încă neverificată** with that username and expiry. A fully verified connection is only reported after a successful approved publication and stored post URL. If it fails, check the exact callback URI, accepted tester invitation, correct Instagram App ID/secret and granted publishing permission. Do not share the callback URL containing its temporary authorization code.
13. **Authorized publishing test:** first choose one harmless finished test Reel and decide you want it publicly posted to `@divinework.store`. Add its stable video URL and caption in Studio, mark AI content accurately, watch the preview and check rights/disclosures. Content needing a mandatory native AI label must be posted manually instead. Select a future date/time, tick the explicit approval box and click **Aprobă și programează**. At this point it is scheduled but still cannot publish while the switch is false.
14. Only when you explicitly authorize that real Instagram test, change **only** `INSTAGRAM_PUBLISHING_ENABLED` to `true` in Vercel and **Redeploy**. This enables approved due Instagram posts; it does not enable customer email or payments. Allow time for the next cron run and Meta video processing. Open the **post URL in the Studio history**, verify the actual Reel on the correct account, and record that result before treating publishing as verified. Turn the switch back to false and redeploy if the test should be the only real post. Unapproved drafts are never published.
15. For ongoing use keep the authorized switch enabled, the scheduler active, and approve each final Reel individually. Check failures and expiry regularly. Click **Anulează** before processing reaches publishing to stop a queued post. Click **Deconectează și anulează coada** to remove the local token; revoke the app in Instagram as well to invalidate access at Meta. For a `publication_outcome_unknown`/`uncertain` result, inspect Instagram before creating any replacement; never click through blindly to duplicate a post.

No DNS changes at Namecheap are needed for Instagram. Keep the working website and business email DNS records intact. Meta app approval, legal/business verification, secrets, real media hosting, a real OAuth grant and an explicitly authorized real publishing test remain personal setup steps. No real connection or publication is claimed by automated mocks.

## Development verification

`npm test` includes Postgres-backed Instagram integration tests using PGlite and mocked official Meta HTTP endpoints: encryption/tampering, state/expiry/replay, wrong account/missing permissions, approval/AI policy, scheduling, concurrent claims, cancellation, rate limits, bounded retries, uncertain publication, permalink recovery, token refresh and browser-role denial. `npm run test:e2e` covers the protected Studio integration UI. `npm run typecheck` and `npm run build` check the application. Dev Instagram storage is process-local and resets on restart; production fails closed without Supabase and migration confirmation. No fabricated mock account is shown as a real connection.

Current first-video-test restriction: Instagram publishing is now source-locked while the Runway single-video workflow is tested. Step 14's environment switch cannot override that lock. See `docs/runway-verification.md`; account connection and queue review still work, but a separate explicitly authorized code change is required to resume publishing.
